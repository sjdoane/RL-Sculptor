## Defaults picked under "no clarifying questions" mode

(Full rationale in `NOTES.md`. One-line summary of each here.)

- **Python interpreter**: switched from uv-provided cpython-3.11 to the
  miniconda cpython-3.13. The uv-provided 3.11's `_ssl.pyd` is blocked by
  Windows Application Control on this machine, which broke `pytest` (anyio
  imports `ssl`). `pyproject.toml` still declares `requires-python = ">=3.10"`
  for portability; only the local `.python-version` points at miniconda.
- **`mujoco` version**: the resolver under `requires-python>=3.10` picks
  mujoco 3.7.0, which has Windows wheels for cpython-3.13. With the
  uv-provided cpython-3.14 the wheel was missing and pip fell to source
  build → `MUJOCO_PATH` error. Pinning Python to 3.13 sidesteps it.
- **Legacy quadruped reward**: kept at `sculptor/reward.py`; tagged in
  NOTES.md as "to migrate to examples/quadruped/ when a Brax/MJX adapter
  lands". Not deleted (would break AME456 env import).
- **Video backend**: `ffmpeg` via subprocess (per spec) AND added
  `imageio-ffmpeg` to the dep set so the binary is bundled — Windows users
  shouldn't need to `apt install ffmpeg`. Adapter prefers system ffmpeg,
  falls back to the bundled binary. **This is one extra dependency beyond
  the spec list**, justified to make rollouts work out-of-the-box.
- **`expected_components = None` in the contract**: declares the gym_sb3
  adapter accepts any components-dict shape from a reward module. Sculptor
  iterations are free to invent new component names; the diagnoser will
  consume whatever it sees.
- **`compute_behavior_metrics` for Phase 1**: spec allowed a stub; I shipped
  a real implementation since the data was already in `trajectory.npz`.
- **`load_adapter` location**: implemented in `sculptor/adapters/base.py` per
  spec; called only from Phase 2's tests/scripts.
- **CLI subcommands**: scaffolded with stub bodies; no inner-loop logic yet.

## What I want you to look at

1. **Python interpreter pin** (`.python-version`). I had to point at your
   miniconda python because the uv-provided one is locked down by Windows
   Defender Application Control. If you want to use uv-managed Python in
   future, the underlying issue is `_ssl.pyd` from
   `C:\Users\SamJD\AppData\Roaming\uv\python\cpython-3.11-windows-x86_64-none\DLLs\`
   being blocked by an Application Control policy. Allow-listing that DLL
   (or unblocking the cpython-3.13 equivalent) lets uv's interpreters work.

2. **`imageio-ffmpeg` was added beyond the original dep list**. Easy to
   drop if you'd rather require system ffmpeg, but Windows users will then
   get a sentinel file instead of a real mp4 unless they install ffmpeg
   themselves.

3. **Hopper-v4 vs Hopper-v5**. Gymnasium emits a deprecation warning every
   import; the spec said v4 so I left it. v5 has identical reward semantics
   for our purposes — trivial swap when you're ready.

4. **20,000-step Hopper policy is intentionally weak** (mean episode length
   = 42, fall_rate = 1.0). That's expected at this budget — it's there to
   prove the plumbing works end-to-end, not to demonstrate a good policy.

5. **The legacy `sculptor/reward.py` + `tests/test_reward_parity.py`** are
   coupled to the AME456 env. Migration to `examples/quadruped/` (with a
   Brax/MJX adapter) is the natural next step but was out of scope tonight.
